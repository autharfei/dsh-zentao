# 开发说明

项目使用 Node.js 原生 ESM 作为 Host，客户端使用 DSH 共享的 React 与 ModuleLoader。运行时没有新增第三方依赖。

## 目录

- `src/`：Host 生命周期、连接、同步、状态存储、HTTP、桌宠适配及客户端。
- `scripts/build.mjs`：从源码生成 `lib/`，把客户端与样式包装为宿主模块。
- `scripts/check-release.mjs`：只读核对 `lib/` 与源码逐字节一致、入口/patch齐全且无需安装时构建；不加载插件代码。
- `scripts/pack.mjs`：构建、检查发布文件，再按固定白名单生成安装包，输出 SHA-256。
- `scripts/verify-live.mjs`：可选的人工联网检查入口，使用操作者本机已保存的连接。
- `test/`：合成数据的单元检查及按需启用的 Chromium 集成检查。

GitHub 安装直接使用仓库中的已构建文件，固定清单内的 11 个 `lib/` 文件必须进入 Git。`dist/`、其他构建输出、本地配置与测试输出仍不进入 Git。发布前运行 `node scripts/pack.mjs`（包含发布一致性检查），并将更新的 `lib/` 与源码一并提交；只检查、不改写文件时运行 `node scripts/check-release.mjs`。不要复制本机 DSH 数据目录到仓库。

## 单元检查

需由操作者自行执行：

```sh
node --test --test-isolation=none
```

`--test-isolation=none` 用于避免受限 Windows 环境对子进程 stdio 管道的限制。构建相关用例会重新生成受跟踪的 `lib/` 及被忽略的 `dist/`。

## 可选 Chromium 检查

客户端富文本检查使用新建的临时浏览器配置；布局检查只读取本机安装包中的框架库和布局 CSS，不启动 DSH 应用，也不使用 DSH 登录态。

PowerShell 示例（路径请替换为自己的环境）：

```powershell
$env:DSH_ZENTAO_BROWSER_TEST = '1'
$env:DSH_ZENTAO_BROWSER = '<Chrome 或 Edge 可执行文件绝对路径>'
$env:DSH_ZENTAO_HOST_ASAR = '<DeepSeek Harness resources/app.asar 绝对路径>'
# 可选：同时启用皮肤背景绘制检查
$env:DSH_ZENTAO_SKIN_CLIENT = '<liang 皮肤 lib/client.js 绝对路径>'
node --test --test-isolation=none
```

未提供宿主 ASAR 时，依赖宿主的布局检查跳过；未提供皮肤源码时，皮肤绘制检查跳过。布局用例对应 DSH `0.2.1-rc.5` 的资源结构，其他宿主版本的资源名称或内部 CSS 可能不同，需要调整用例适配。

若需要保存绘制截图，设置 `DSH_ZENTAO_PAINT_EVIDENCE_DIR` 为自行创建的本地目录。截图可能带有个人信息，不应提交到公开仓库。

## 0.1.5 桌宠联动

新增 `src/alert-images.js` 只管理上传位图；由插件存储目录保存，桌面读取使用仅绑定127.0.0.1的随机端口及启动随机访问标识。浏览器预览继续走DSH同源路由，图片原始内容不会写入Git或安装包。

通知投递与快照扫描分开，按任务/Bug合并，等待上一条实际配置的显示时长后再发送下一条。卸载或切连接时中止队列；已受理项持久标记delivered，未受理项保留到后续扫描重试。动作和配图失效时可降级文字，并显示warning。

本轮已更新受新增默认字段和异步投递影响的既有测试定义，但未执行任何测试。安装验收应由操作者分别检查：旧配置升级、两种独立配置、图片上传/替换、关闭设置页后提醒、两类同时到达、图片/动作失效、桌宠未启用/睡眠/被占用、卸载后服务停止及重新启动配置恢复。

## 0.1.6 业务操作

新增 `src/operations.js` 负责动作元数据、字段与状态白名单、提交前版本校验以及官方端点映射；新增 `src/client-operations.cjs` 实现列表/详情共用入口与操作表单。Runtime维护对象并发与请求ID去重，ZentaoClient的业务写发送一次，超时或服务异常返回结果未知，不自动重新登录后重放写请求。

写成功从上游返回对象更新本地行和通知基线；mutationRevision阻止已在途的旧快照回滚这次更新，再后台重读列表。响应不等待整站扫描完成；本地持久化失败仍保留已应用的结果与告警。写操作在途期间拒绝切换连接，卸载会中止网络并等待已发操作收尾。

任务取消和Bug转任务使用原站专用表单；多人/父任务汇总及完整富文本/附件编辑也保留原站流程。接口证据、字段语义和人工验收点详见 [操作能力说明](operations.md)。已更新既有客户端测试fixture的模块加载器以支持新增操作组件；本轮未运行测试或触碰真实业务记录。

## 0.1.7 界面可读性

`src/client.css` 统一字体/字重token，辅助文字至少12px、表格13–14px、正文14px、主标题26px；表头、标题和按钮使用700字重。主要按钮/筛选控件38px、行内动作30px，表格增加行间距，详情/通知/设置与操作表单采用同一层次。1120px以下容器中详情用覆盖抽屉，窄屏保留字号并滚动表格/导航或换行控件。主题、焦点、减少动画偏好与macOS顶部clearance沿用既有规则。

`src/client-operations.cjs` 仅增加按钮的 `data-action` 展示标识，以区分完成/解决和取消的语义色；事件、状态、权限与提交链路不变。`src/client.cjs` 的工作台跳转/失败入口接入现有主题hook及样式根，让提示与重试按钮继承同一套字体和主题token。人工检查清单见 [界面样式说明](ui.md)。本轮仅进行语法、构建、归档检查与静态审查，不运行功能测试、GUI验收或安装卸载。

## 0.1.8 页签滚动与链接截图

页签容器显式设置 `overflow-y:hidden`，保留必要的横向滚动；选中下划线移入按钮边界，避免因横向auto联动及边缘溢出出现纵向滚动条。

富文本清理原先在递归之前将整个a节点替换为textContent，链接包裹的图片会丢失。现在先净化子节点，再通过既有非白名单标签拆包逻辑移除链接本身，保留合法截图及格式。图片仍只转为固定ID代理，原始href、事件属性、脚本和不支持的图片地址均不放行；CSP、sandbox与代理认证没有放宽。补充了对应的浏览器DOM回归定义，但未执行任何测试或真实图片请求。没有现场网络证据，不能将此代码缺陷认定为用户所见全部图片失败的唯一原因；接口权限、原始地址格式等剩余情况仍以原站查看为准。

## 0.1.9 GitHub 直接安装

修复源码仓库忽略整个 `lib/`、导致Git安装缺少运行入口的问题。现在仅放行固定11个Host/Client构建文件；不存在安装时执行的prepare/preinstall/install/postinstall脚本。`buildArtifacts()`只读取源码并构造预期字节，`build()`写入这些文件，`checkRelease()`只读比较实际文件与预期，拒绝缺失、过期和额外输出；pack先build再check。包清单和插件业务入口保持原有契约。

维护者发布步骤：修改源码 → `node scripts/pack.mjs` → `node scripts/check-release.mjs` → 检查并提交源码、清单与lib → 推送。干净克隆只需运行check即可确认仓库产物完整，不需要安装依赖或执行插件。用户可在DSH输入GitHub仓库链接；GitHub ZIP需要先解压后使用包目录绝对路径，或使用本地tgz。网络下载失败与包入口缺失是两个阶段的问题。

本轮仅语法、构建、发布文件一致性、归档内容及远端文件树检查；未执行测试、安装或GUI验收。

## 提交范围

测试应使用 `example`、`invalid`、`.test` 域及合成账号，不放真实站点、响应、任务标题、截图或密码。不要提交 `.env`、连接文件、通知状态、私钥、凭据、访问令牌或日志。

上传前检查 `git diff --cached` 与 `git status`。安装包只包含固定构建白名单，不包含测试、调试输出或用户存储；Git仓库额外包含源码、通用测试和构建工具。
